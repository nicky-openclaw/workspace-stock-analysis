# 启动K框架 SOP v4.4

> 更新日期：2026-03-17
> 版本：v4.4（新增板块数据Browser备用方案）

---

## 框架概述

启动K选股框架，核心理念"在对的位置放量启动"。

---

## 触发条件

用户发送条件股截图并提及"启动K"时触发。

---

## 评分体系

- 第一层趋势质量20分（白线≥黄线+8，白线向上+7，黄线向上+5，近期金叉+5）
- 第二层启动K信号质量40分（倍量≥2x+30，1.5-2x+18，大阳线+10，余热+8）
- 第三层启动位置质量25分（黄线附近+25，白线附近+15，站回白线+10）
- 第四层涨幅确认15分（涨停+15，≥5%+15，≥2%+8，≥0%+3）
- 硬淘汰：白线＜黄线 / 收盘跌破白线 / 放量下跌

### 启动类型识别
- 趋势扭转型
- 趋势改变型
- 趋势延续型

---

## 执行流程

1. **图片识别**：使用 minimax-understand-image skill 识别条件股截图
2. **写入stocks.json**：将识别的股票写入 `qdk_output/qdk_stocks.json`，**必须包含 date 字段为当日日期**（格式：YYYYMMDD）
3. **K线拉取**：qdk_step2_fetch.py（脚本会自动检查日期是否匹配，不匹配则报错退出）
4. **指标计算**：qdk_step3_calc.py
5. **综合评分**：qdk_step4_score.py
6. **板块效应分析**：
   - 运行 `python3 scripts/qdk_sector_analysis_v3.py` 获取个股所属板块和资金流
   - **【重要】API失败时直接切换 Browser 补齐数据**：
     - 打开 https://data.eastmoney.com/bkzj/hy.html 查询行业资金流
     - 或打开个股页面 https://quote.eastmoney.com/szXXXXXX.html 查询所属板块
   - 手动补充到 sector_analysis.json
7. **输出报告**：按格式输出（TOP5）
8. **清理截图**：删除 patrol 目录图片

## 输出格式（必须完整）

### 1. TOP5
评分前5只股票表格

### 2. 关键指标表
| 字段 |
|------|
| 代码 |
| 名称 |
| 白线 |
| 黄线 |
| 白>黄 |
| 涨幅 |
| 量比 |
| J值 |
| RSI3 |
| B1 |
| 评分 |

### 3. K线详细形态分析

每只股票格式（4行，纯正文不加粗）：

第一行：白线/黄线数据，间距，MA状态，位置，放量，涨跌
第二行：RSI｜J值｜涨幅（纯数字，用 ｜ 分隔）
第三行：评分构成：关键加分项+分值（≤6项，| 分隔）
第四行：⚠️ 风险（🔴 标记RSI>85或极高风险标的）

**规则**：全文不加任何 **加粗**，不用"趋势："、"量能："等标签前缀；数值全保留，文字精简。

### 4. 板块效应分析
| 字段 | 说明 |
|------|------|
| 所属行业 | 申万/同花顺行业 |
| 所属概念 | 热门题材概念（如有） |
| 板块走势 | 强势/震荡/弱势 |
| 板块主力净流入 | 金额 |
| 板块助攻 | 强/中/弱/无 |

**板块数据查询优先级：**
1. 行业资金流（东方财富 > 数据中心 > 行业资金流）
2. 概念资金流（同上 > 概念资金流）
3. 地域板块资金流

**【关键】API失败时的备用方案：**
- 当东方财富API返回空数据时，**直接切换 agent-browser**
- 浏览器打开 https://data.eastmoney.com/bkzj/hy.html 可获取今日板块资金流向
- 浏览器打开个股详情页可获取所属板块信息
- 无需等待API修复，浏览器方案更可靠

**查不到时的处理：**
- 标注为"细分行业，需人工确认"
- 可通过股票详情页的"所属板块"查看关联概念
- 必要时查询概念资金流补充

附：当日热点板块/资金流入前5

### 5. 明日交易决策 Checklist
| 检查项 |
|--------|
| 白线>黄线 |
| 竞价量比>2 |
| 板块效应 |

## 注意事项

1. **必须使用 minimax-understand-image skill 识别图片**
2. **识图后必须写入 qdk_stocks.json**（包含 date 字段为当日日期），再执行后续脚本
3. 脚本会自动检查日期，不匹配会报错退出
4. 禁止跳过任何输出字段
5. 每只TOP5都必须有详细分析
6. 任务完成后清理 patrol 目录截图
7. 每次分析必须有风险提示

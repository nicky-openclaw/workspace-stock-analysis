## 📖 砖型图核心定义

**砖型图**：衡量股价动能的量化指标，来自 `indicators/zhuantxing.py`
- 今日砖型值 > 昨日砖型值 → **走强**（动能增加）
- 砖型值 > 100 → **强势区域**
- 砖型图绿转红 + 红柱 ≥ 绿柱2/3 → 超短线买入信号（模式B）

**B1/B2信号**：来自 `indicators/library.py`，不得自编

## 📋 执行步骤

### Step 1 — 图片识别（并发子代理模式）

**⚠️ 多图识别铁律（2026-03-09）**：
- image skill 传入 `images` 数组时**只处理第1张**，其余全部忽略
- **必须为每张图片单独 spawn 一个子代理**，每个子代理只识别1张图
- N 张图 → 同时 spawn N 个子代理（并发）→ 等所有子代理完成 → 汇总去重
- 禁止使用 `images=[...]` 数组批量传入多张图
- 禁止串行识别（逐张等待太慢）

**执行流程**：
```
主Agent收到 N 张图
→ spawn 1个子代理A
→ 子代理A 串行调用 image 工具 N 次（每次1张）
→ 汇总去重 → 写入 ztx_stocks.json
```

- 每张图独立识别，不能遗漏
- 输出去重后完整代码清单，标注市场前缀（sh/sz/bj）

**输出文件**：`ztx_output/ztx_stocks.json`

### Step 2 强制校验（优化为并行调用）

> ⚠️ **2026-03-09 优化**：同时调用两个接口，一次获取全部数据

**正确做法**：K线接口（算均线+砖型值）+ 实时接口（直接获取涨跌幅），**并行执行**

**关键：实时API本身包含涨跌幅，直接使用！**
```

- 字段4: 昨收

```

**禁止**：自己用K线收盘价计算涨幅 ✅
**正确**：直接取实时API的涨跌幅字段 ✅

**数据源组合**：

| 用途 | 数据源 | 调用方式 |

| 计算MA均线/砖型值/位置 | 腾讯K线API（akshare stock_zh_a_hist_tx） | 获取120日K线 |
| 获取涨跌幅 | 腾讯实时API（qt.gtimg.cn） | 实时API字段32 |

**腾讯实时API调用**：

### Step 3 — 指标计算（子代理C）

**必须计算**：
| 指标 | 公式来源 |
|------|---------|
| MA5、MA10、MA20 | 标准均线 |
| MA20方向 | 今日MA20 vs 昨日MA20 |
| J值（KDJ） | indicators/library.py |
| RSI（14日） | indicators/library.py |
| 今日砖型值 / 昨日砖型值 | indicators/zhuantxing.py |
| 砖型图方向 | 今日砖型值 > 昨日砖型值 |
| 今日量 / 昨日量 / 20日均量 | 标准量能 |
| B1信号 | indicators/library.py check_b1() |
| B2信号 | indicators/library.py check_b2() |
| 涨幅 | (今日收盘 - 昨日收盘) / 昨日收盘 × 100 |

**输出文件**：`ztx_output/ztx_indicators.json`

### Step 4 — 综合评分（子代理D）

#### 🔴 硬淘汰条件（不满足直接排除，不进入评分）
| 条件 | 规则 |
|------|------|
| 白线在黄线之下 | MA5 < MA20 → 淘汰 |
| 当日跌破白线 | 今日收盘 < MA5 → 淘汰 |
| 砖型图持续走弱 | 连续3日砖型值下降且今日砖型值 < 0 → 淘汰 |

#### 📊 四层评分 + B信号辅助（满分100分）

> 2026-03-17 优化：B信号从独立评分层改为辅助加分，砖型图和B1/B2是两套独立体系

**第一层：趋势质量（20分）**

| 指标 | 分数 | 条件 |
|------|------|------|
| 白线≥黄线（多头基础） | +8分 | MA5 ≥ MA20 |
| MA20方向向上 | +7分 | 今日MA20 > 昨日MA20 |
| 双线确认 | +5分 | 白线≥黄线 且 MA20向上 |

**第二层：砖型图信号（40分）——核心层**

砖型图是短线核心信号，强红（绿转红且红绿比≥2/3）是最强买入信号。

| 指标 | 分数 | 条件 |
|------|------|------|
| **强红** | **+30分** | 绿转红 且 红柱高度≥绿柱2/3（核心信号） |
| 弱红 | +8分 | 绿转红但红绿比<2/3（仅参考） |
| 红柱强化 | +15分 | 今日砖型值>0且走强（非绿转红时取） |
| 砖型走强 | +8分 | 今日砖型值 > 昨日砖型值（可叠加） |
| 砖型值>100 | +5分 | 进入强势区域（可叠加） |
| 连续3日走强 | +5分 | 近3日砖型值递增（可叠加） |

> 强红/弱红/红柱强化取最高档，其他可叠加，上限40分

**第三层：量能验证（15分）**

| 指标 | 分数 | 条件 |
|------|------|------|
| 放量（量比≥1.5x） | +15分 | 今日量 ≥ 昨日量 × 1.5 |
| 地量（最佳缩量状态） | +10分 | 今日量 < 20日最低量 × 1.2（未满足放量时取）|

**第四层：涨幅确认（15分）**

| 指标 | 分数 | 条件 |
|------|------|------|
| 涨停 | +15分 | 按市场涨停幅度判断 |
| 强势（5-9.9%） | +10分 | 沪深主板 5-9.9% |
| 中势（2-5%） | +6分 | |
| 弱势（0-2%） | +2分 | |

**B信号辅助加分（上限15分，锦上添花）**

> 砖型图和B1/B2是两套独立体系，B信号作为辅助验证，不作为主要评分依据

| 指标 | 分数 | 条件 |
|------|------|------|
| B1完整触发 | +15分 | library.py check_b1() 全部满足 |
| B2信号触发 | +10分 | library.py check_b2() 全部满足（B1未触发时取） |
| J值超卖（J<14） | +5分 | B1/B2均未触发时 |
| RSI超卖（RSI<23） | +3分 | 可与J值叠加，上限8分 |

> **总分上限：100分**

## 复盘流程

### 时间规则
- 同日：当天选股 → 次日收盘后复盘
- 跨周：周五选股 → 下周一复盘
- **复盘涨幅必须用K线收盘价计算，禁止用实时价格**

### 复盘步骤
1. 读取上一交易日选股记录（`memory/patrol/YYYY-MM-DD.md`）
2. 用K线API获取复盘日收盘价
3. 计算涨幅：`(复盘日收盘 - 选出日收盘) / 选出日收盘 × 100`
4. 输出复盘表（选出日收盘、复盘日收盘、涨幅、评价）
